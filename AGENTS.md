# AGENTS.md

## Цель проекта

Создать простой, аккуратный и полностью рабочий веб-To-Do List.

Приложение должно позволять пользователю:

- создавать задачи;
- просматривать список задач;
- отмечать задачи выполненными;
- возвращать выполненные задачи в активные;
- редактировать задачи;
- удалять задачи;
- сохранять состояние после перезапуска приложения.

Проект должен оставаться максимально простым и понятным.

---

Использовать:

- Python 3;

## Функциональные требования

### Задача

Каждая задача должна иметь минимум:

- `id`;
- `title`;
- `completed`;
- `created_at`.

Дополнительно можно добавить:

- `description`;
- `priority`;
- `due_date`.

Дополнительные поля не должны усложнять базовую реализацию.

### Создание задачи

Пользователь вводит текст задачи и нажимает кнопку добавления.

Пустую задачу создавать нельзя.

После создания задача сразу появляется в интерфейсе.

### Выполнение

У каждой задачи должен быть checkbox или аналогичный элемент.

При отметке задача получает состояние `completed`.

Выполненная задача должна визуально отличаться от активной.

### Редактирование

Пользователь должен иметь возможность изменить текст существующей задачи.

### Удаление

Пользователь должен иметь возможность удалить задачу.

Удаление должно происходить только для выбранной задачи.

### Фильтрация

Добавить простые фильтры:

- Все;
- Активные;
- Выполненные.

## Интерфейс

Интерфейс должен быть минималистичным и удобным.

Основная страница:

```text
┌─────────────────────────────────────────┐
│              My To-Do                  │
│                                         │
│ [ Что нужно сделать?          ] [ + ]  │
│                                         │
│ ☐ Купить продукты                       │
│ ☑ Обновить сервер                       │
│ ☐ Позвонить клиенту                     │
│                                         │
│ Все | Активные | Выполненные            │
└─────────────────────────────────────────┘
```

Требования:

- адаптивность для телефона и компьютера;
- нормальные отступы;
- читаемые размеры текста;
- понятные кнопки;
- выполненные задачи можно отображать зачёркнутыми;
- избегать перегруженного дизайна.

Не добавлять декоративные элементы, не влияющие на удобство.

## Backend

Flask отвечает за:

- отображение страницы;
- получение списка задач;
- создание задачи;
- изменение задачи;
- изменение статуса;
- удаление задачи.

Допустим REST-подобный API:

```text
GET    /api/tasks
POST   /api/tasks
PUT    /api/tasks/<id>
DELETE /api/tasks/<id>
```

Пример объекта:

```json
{
  "id": 1,
  "title": "Обновить сервер",
  "completed": false,
  "created_at": "2026-08-15T12:00:00"
}
```

API должен возвращать корректные HTTP status codes.

## База данных

Использовать SQLite.

Таблица:

```sql
CREATE TABLE IF NOT EXISTS tasks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    completed INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL
);
```

База должна автоматически создаваться при первом запуске приложения.

Не требовать от пользователя ручного создания таблиц.

## JavaScript

JavaScript должен оставаться небольшим.

Использовать его только для:

- отправки запросов к API;
- добавления задач;
- переключения статуса;
- редактирования;
- удаления;
- фильтрации;
- обновления интерфейса без полной перезагрузки страницы.

Избегать глобального состояния и сложных абстракций.

## Правила реализации

Следовать принципу:

> сначала самая простая рабочая реализация, затем улучшения.

Не создавать архитектуру "на будущее", если она пока не нужна.

Предпочитать:

```python
def create_task():
    ...
```

вместо большого количества абстракций вроде:

```text
TaskService
TaskRepository
TaskManager
TaskFactory
TaskController
```

для приложения такого размера.

## Безопасность

Минимум:

- проверять пользовательский ввод;
- не допускать пустых задач;
- не формировать SQL через конкатенацию строк;
- использовать параметры SQL;
- экранировать пользовательский вывод;
- не хранить секреты непосредственно в коде.

## Обработка ошибок

Ошибки API должны возвращаться в JSON:

```json
{
  "error": "Task not found"
}
```

Интерфейс не должен ломаться при ошибке запроса.

Пользователю следует показать короткое понятное сообщение.

## Тестирование

Добавить минимальные автоматические тесты для:

- создания задачи;
- получения задач;
- изменения задачи;
- завершения задачи;
- удаления задачи;
- попытки создать пустую задачу.

Использовать `pytest`.

Перед завершением задачи агент должен запустить:

```bash
pytest
```

Если тесты падают — исправить проблему до завершения работы.
